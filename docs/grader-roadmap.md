# Grader 开发路线

`grader/grade` 当前刻意保持最小——足够覆盖 Ch 1–4。后续章节会引入新概念，需要扩展断言能力时记录在这里。

## 当前能力（2026-04-23）

- 退出码（`exit:`）
- stdout / stderr —— 精确、包含、正则
- 文件系统 —— 存在性、内容包含、内容正则
- `setup:` 钩子和 `timeout`
- 测试在干净 tmpdir 里运行；`$EXERCISE_DIR` 指向练习目录

**稳定承诺**：以上语义不会变更，未来只做加法。

## 按章节预计的扩展

### Ch 5（I/O、文件描述符）
- 多流重定向用现有的 `files:` + `stderr:` 已能验证，无需新增。

### Ch 6（进程、退出码）
- **时长窗口** —— `min_duration` / `max_duration`，用来证明并发性（4 个 1 秒任务必须 ≤ 2 秒完成）。
- **stdin 字段** —— 目前需要在 `run:` 里用 shell 重定向，加一个一等的 `stdin:` 字段更可读。

### Ch 7（子 shell、进程替换）
- 行为断言够用，预计无需改 grader。

### Ch 8（模式匹配）
- 无需改 grader。

### Ch 9（健壮脚本）
- **shellcheck 集成** —— `lint:` 字段对 starter 跑 shellcheck，超过级别即失败。
- **幂等性检查** —— `idempotent: true` 把测试连跑两次，断言第二次结束后 fs 状态等于第一次。备份脚本、迁移脚本类必备。
- **禁用命令检查** —— `forbid: [sed, awk]` 静态 grep starter，验证学习者用了本章想教的语法而不是绕过去。**延后实现**，等真有练习需要时再加。

### Ch 10（综合项目）
- **rubric 评分** —— 主观清单，可能保持人工评审，不强求自动化。
- **多文件项目** —— 已经支持（测试只是引用 `$EXERCISE_DIR` 下不同文件）。

## 跨章节的改进项（nice-to-have）

- stdout 不一致时输出 unified diff，比当前的 repr 双行更友好。
- `weight:` 字段，让单个测试能拆出子分数。
- JSON 输出模式，方便对接 CI / 进度看板。
- `-v` 模式打印每个测试的完整 stdout/stderr，调试用。

## 不会做的事

- 依赖网络的断言。grader 必须完全离线运行。
- 在 `grader/grade` 里写章节专属逻辑。新章节通过断言词汇表来表达自己；词汇表不够就扩展词汇表。
- 引入测试框架抽象。grader 应该一坐能读完，复杂度上去就违背初衷。

## 可视化模块（独立工作流）

Ch 5 和 Ch 7 计划配交互式可视化（管道/fd 数据流、进程树）。这部分是纯前端项目，预计单独建仓，不进 grader 的路线图。
